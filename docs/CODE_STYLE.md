# Стандарт оформлення коду

Для власного JavaScript використовується ESLint із flat config та Prettier. Зафіксовані версії зберігаються у package-lock.json. Налаштування VS Code рекомендують розширення ESLint і Prettier та вмикають форматування під час збереження.

- UTF-8, LF, відступ два пробіли, одинарні лапки в JavaScript, крапка з комою, trailing comma.
- Орієнтир довжини рядка — 100 символів; остаточне перенесення визначає Prettier.
- Назви функцій і змінних — camelCase, класи — PascalCase, константи наборів/запитів — UPPER_SNAKE_CASE.
- Блоки if/for/while завжди мають фігурні дужки. Порівняння — через === та !==.
- ESLint забороняє невизначені й невикористані змінні, недосяжний код та дубльовані імпорти.
- Публічні функції, класи та методи мають JSDoc-коментар із призначенням. Нетипові обмеження пояснюються біля відповідного коду.
- SQL належить репозиторію, мережеві Wikidata-запити — клієнту відкритих даних, сценарії — сервісу, DOM — інтерфейсу.
- Дані показуються через textContent. Помилки мережі не підміняють перевірений каталог частково завантаженими записами.

Команди:

```powershell
npm run format
npm run check
npm run test:coverage
```

GitHub CI відхиляє зміни з порушенням правил ESLint або форматування Prettier. Код стороннього Oxigraph у dist/vendor не переформатовується й не перевіряється нашими правилами. Початкові JSON-дані також виключені з форматування, щоб не створювати зайві зміни даних.
