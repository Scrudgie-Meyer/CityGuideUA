# Відповідність вимогам проєкту

| Вимога                      | Реалізація та доказ                                                                                                        |
| --------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| Модуль відкритих даних      | Окремий WikidataClient, пакетні HTTPS-запити, тайм-аут, перевірка країни та тверджень, збереження JSON-джерел              |
| Сховище                     | Постійна серверна SQLite: cities, source_entities, rdf_triples, catalog_state                                              |
| Рівень доступу до даних     | CityRepository з параметризованим SQL, індексами, транзакцією та backup                                                    |
| Рівень програми             | CatalogService, атомарний імпорт, оновлення каталогу, Worker для SPARQL                                                    |
| Рівень інтерфейсу           | HTTP API, окремий браузерний API-модуль та DOM-представлення                                                               |
| Часткове покриття тестами   | Домен, справжні Wikidata-fixtures, перезапуск SQLite, 13-й запис, rollback, backup, мережеві помилки, SPARQL та HTTP       |
| Стандарт коду               | ESLint, Prettier, EditorConfig, npm run check, обов’язкова перевірка CI                                                    |
| Коментарі та документування | JSDoc для власних функцій і методів, README та документація архітектури                                                    |
| GitHub                      | Workflow підготовлено; публікацію в особистий репозиторій і налаштування захисту main виконує власник через VS Code/GitHub |

Наявність workflow у файлах не підтверджує публікацію коду та не вмикає автоматично захист main. Цей зовнішній крок потрібно завершити в обліковому записі власника. Конфігурація Railway також потребує реального Volume: файлове сховище контейнера без нього не є постійним.

Перевірка після реалізації: 28 тестів завершилися успішно. Це часткове покриття; DOM не покривається цими Node-тестами. Команда test:coverage формує відсотки для модулів, які завантажені тестами, а не для всього інтерфейсу. Docker локально недоступний; збірка та smoke-перевірка контейнера виконуються в GitHub CI після публікації.
